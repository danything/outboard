# 配線の書き方

銅 (線・ビア・面) は `lib/routing/` に、ブロックごとの別ファイルで書く。見本は [`lib/routing/buck.tsx`](../lib/routing/buck.tsx) (降圧)。

## ファイル

| ファイル                  | 持ち場                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lib/routing/<block>.tsx` | `lib/placement.ts` のブロック 1 つ (`pdPc`・`pdCharger`・`usb`・`input`・`mcu`・`slot`・`boost`・`switch12`・`buck`)。自分の領域 (`BLOCKS[名前].region`) の中だけ                                                                                                                                                                                                                                                                                                                                         |
| `lib/routing/trunks.tsx`  | 幹線 (統合役): うらの GND の面と、それをつなぐビア、D1・D2 の放熱のうらの VIN・VBUS の面、どのブロックの領域にも入らない所の線と面。**ブロックの領域の中は、通り抜ける線も含めて、そのブロックの担当が受け渡しの点から点まで引く** いま: VBUS1 (pdPc から usb の領域を通って input まで。usb の担当は VBUS1 を描かないので、J4 のプラグの下も幹線)・VBUS2 (pdCharger と input の間)・PERST# (mcu の点から slot の線まで。VBUS1 と 12V の列を 1 回ずつうらでくぐる)。x 74.5〜83 の 3.3V の行は slot の領域 |
| `lib/routing/kit.tsx`     | 線・ビア・面の部品と座標の関数。**銅はこれでしか置かない**                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `lib/routing/index.tsx`   | 並べるだけ。触らない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

ほかのブロックとは、`lib/placement.ts` の `HANDOFFS` の点 (座標・層・幅) で受け渡す。自分の領域の辺のその点まで引いて止める。点を動かしたいときは、相手と幹線の担当に言ってから `HANDOFFS` を直す。
部品を動かすのは `lib/placement.ts` の自分のブロックの中だけ。

## 層 (2 層)

| 層       | 中身                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| `top`    | 部品・信号・電源の面と線。**配線はおもてで済ませる**                          |
| `bottom` | GND の面 (基板全体。`trunks.tsx`)。線は、おもてで交差する所をくぐる短い橋だけ |

- **GND**: パッドのそばに `Via` を落としてうらの面へ。おもての線で引き回さない
- **+3V3**: 面が無い。おもての面と太い線で配る (J3 までは幹線)。細い枝 (LED、Q3 のゲート) は 0.3mm の線
- **うらの線**: 1 本ずつ理由を書く。くぐったらすぐおもてに戻す (1 か所 10mm がめやす。検査はしない)。うらの面を長く切らない。
  めやすを超えているのは、VIN の帯をくぐる EN_12V 13.0・Q2_G 12.8・EN_3V3 12.0mm (帯の幅そのもの)。PERST_N は slot の 1 か所が 10.0mm。うらの GND が 1 枚につながっていることは検査 `groundPlane` が見る
  並べてくぐるときは束ねて 1 か所で、切れ目の両側に GND のビアを 1 個ずつ置く (おもてに GND の銅がある所だけ。無いと `via_dangling`)。合計のめやすは基板全体で 150mm (いまは 162mm。`bottomTotal` の上限は 500)
- **うらに線を置かない所** (`bottomUnder`): 降圧・昇圧の部品の下、USB の D+/D− の下 (0.5mm 以内)。FB はおもてだけ
- **ビア**: 貫通だけ。穴 0.3・外径 0.6 以上

### 2 層で詰まる所の逃がし方 (方針。決めるのは幹線の担当)

| 所                                     | 逃がし方                                                                                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| J1 の南の VBUS のパッド                | USB の線の下はくぐれない。殻の下 (パッドの列より後ろ) のうらを 0.5mm 以上の線で北のパッドへ渡す。ビアは殻の外 (`underShell` は殻の下のビアを網を問わず落とす) |
| J1_CC1 が USB の束の反対側へ渡る       | U1 の真北 (x 10.5) で、対の下をうらで直角に 1 か所くぐる (4.15mm)。`bottomUnder` の例外はこの 1 本だけ (`checks/rules.ts` の `USB_BOTTOM_CROSSINGS`)          |
| +3V3 → Q3 のゲートが降圧の入力を横切る | 降圧の南 (C9 の先) で VIN の面の下を 4mm くぐる (`buck.tsx` に入っている)                                                                                     |
| PERST_N がうらを南北に長く走る         | おもてを主にして、VBUS1 と 12V の列をくぐる所だけうら。1 か所 10mm がめやす                                                                                   |
| VIN の帯のうら                         | 取り合いの順は、D1・D2 の放熱の VIN の面 → 帯をくぐる信号 3 本 (束ねて 1 か所) → C4・C5 の GND のビア (帯の外)。場所は幹線が `HANDOFFS` に出す                |
| I2C2 が VBUS2 の帯を横切る             | 2 本を並べて、帯に直角にうらでくぐる。VBUS2 のおもての面は切らない                                                                                            |
| D1・D2 の放熱                          | おもての面 + カソードのそばの 0.8mm のビア 6 個ずつで、うらに VIN の面 (幹線)。うらの GND を削るので大きさは幹線が決める                                      |

## 座標

**設計の座標** (`lib/geometry.ts`): 原点は後ろ (ブラケット側) の角、x は右、y はカードから離れる向き、mm。`lib/placement.ts`・`HANDOFFS`・`docs/mechanical.md` と同じ。tscircuit の座標 (y が上) には `kit` が直すので、配線では使わない。

- `pad("U3", 3)`・`pad("J3", "B8")`: パッドの中心 (名前は `lib/footprints.ts` のパッドの名前。ほとんどは番号)
- `center("L1")`: 部品の中心
- `blockFrame("buck")(x, y)`: ブロックのローカル座標 (`placement.ts` で部品を置いている座標) → 設計の座標
- `handoff("EN_3V3", "switch12", "buck")`: 受け渡しの点 (`HANDOFFS` から引く。**座標を写さない**)
- `bun tools/pads.ts buck` (ブロック名か部品名): パッドの位置と大きさ、受け渡しの点の一覧

## 部品

```tsx
<Track net="EN_3V3" width={0.2} layer="top" points={[pad("U3", 2), { x: 85.05, y: 31.45 }, { x: 83.5, y: 31.45 }]} />
<Via net="GND" at={{ x: 87.9, y: 31.8 }} {...VIA.signal} />      {/* 穴 0.3・外径 0.6。電源と熱は VIA.power (0.4・0.8) */}
<Vias net="GND" at={[p, q, r]} {...VIA.signal} />
<Pour net="VIN" layer="top" outline={[{ x: 85.4, y: 30.45 }, …]} />   {/* outline がそのまま銅の形 */}
```

- `Track` は 1 つの層の折れ線。層を変えるときは、同じ点に `Via` を置いて、別の `Track` を続ける
- `Pour` の中のほかのネットの銅は 0.2mm あけて切り抜かれる。外形からは自分で 0.3mm 離す。面どうしは重ねない
- ネットの名前は `lib/nets.ts` (まちがうと型エラー)。幅・穴・外径が製造の下限を下回るとビルドが落ちる

## やってはいけないこと

- `<trace>`・`<via>`・`<copperpour>` をじかに書く (`pcbPath` の座標は部品のローカルで回転込み、`via: true` は穴 0.2mm、ネットへつなぐ線は幅が効かない、面は outline から縮む)
- 自動配線を使う (`routingDisabled` を外さない)
- 電源 (`checks/rules.ts` の `POWER_PATHS`) を細い線で引く。面か、決まりの幅以上の線で
- 降圧・昇圧・USB の線の下のうらに線を通す。うらに GND 以外の面を置く (幹線の担当だけ)
- `lib/routing/index.tsx`・`kit.tsx`・ほかの人のファイルを触る (要るときは統合役へ)

## 落とし穴 (各担当が踏んだもの)

- **同じネットの面 2 つが辺を接すると、KiCad が `zones_intersect`** を出す。0.3 あけて、両方に重なる太い線でつなぐ (`slot.tsx` の `ROW_GAP`・`input.tsx` の降圧へのつなぎ)。面どうしは線・パッド・ビアを通してしかつながらない (自前の検査も同じに数える)
- **うら側にしか銅のつながりが無いビア**は、KiCad の `via_dangling` の警告になる (除外されない)。ビアの真下に同じネットの銅 (線か小さな面) を置く
- **J3 のコートヤードは y 9.0 まで**。おもての部品は y 9 より北 (カード側) に置けない (ビルドで落ちる)
- **閉じたはんだジャンパー (JP3〜JP6) の橋は描かない**。部品の中の銅の橋で結ばれている。線はパッドで止める (KiCad ではネットタイ)
- `Pour` の外形は時計回りに直して渡している (反時計回りで tscircuit が落ちる形がある)。面は外形のとおりに塗られ、ほかのネットの銅だけ 0.2 で切り抜かれる
- 受け渡しの点では、両側の銅が点に届いていること (検査 `handoffs`)。点の手前で止めない。面の辺から 0.3 あけたときは、つなぐ線が点を通る
- wslc の `run --name` は名前が既存のコンテナと重なると失敗する。続けて `exec` を打つと、**古いほうのコンテナ** (別のフォルダをマウントしたもの) で動いてしまう。名前に自分の持ち場を入れ、使い終わったら消す
- `wslc ps` はコンテナの名前を途中で切る。名前で grep せず、コンテナ ID で見る
- `bun run snapshot --update` が「All snapshots already up to date」と出しても、絵が描き直されていることがある。`git status` で確かめる
- 絵がぶつかったら、`__snapshots__` は main の側を取ってから描き直すのが早い (`git checkout origin/main -- __snapshots__`)
- 手元で `kicad-cli` を動かすときは、`tools/outboard.kicad_dru` を `dist/index/kicad/index.kicad_dru` に写す。写さないと KiCad の既定の決まり (間隔 0.2・外形 0.5) で見られる
- **パッドの中にビアを置くとビルドが止まる** (`pcb_placement_error`: Via hole overlaps SMD pad)。EP の放熱のビアはパッドの外に出して線でつなぐ
- USB の線を**パッドの中心から**引き始めると、うらの線との間隔で `bottomUnder` に掛かることがある。パッドの端から引く
- 絵 (`__snapshots__`) はほぼ全部の PR でぶつかる。マージは「main を取り込む → `snapshot --update` で描き直す → push → チェックが出そろって全部 pass、かつ main がそのあと動いていない」ときだけ。動いていたらやり直す

## 手元での確かめ方

README の「作り方」のコンテナの中で:

```sh
bun run build && bun run check     # ビルド (tscircuit の検査) → 型・テスト・自前の検査
bun run snapshot --update          # 絵を描き直す。__snapshots__/index.circuit-top.snap.svg・-bottom を見る。差分ごとコミット
bun run lint
```

- `bun checks/run.ts` の出力のうち、製造の条件 (`trackWidth`・`viaSize`・`clearance`・`holeToCopper`・`edgeClearance` など) は 1 件でも落ちる。
- `bun run check` は `--strict`。指摘が 1 件でもあると落ちる。配線を試している途中は `bun checks/run.ts` (--strict なし) で、配線に頼る指摘を `(open)` と出して見る
- KiCad の DRC (CI の `kicad-drc`) は、`lib_footprint_issues` のほかは全部落ちる (未接続・ぶら下がりも)
