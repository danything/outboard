# フットプリント

全部品のランド (`lib/footprints.ts`) を、メーカーのデータシートの推奨ランドと突き合わせた結果と、ランドのデータの出どころを書く。
**実物の部品を載せて確かめたものは無い** (試作前)。数字はデータシートの図を読んだものである。

## 決まり

- 単位は mm。原点は部品の中心、x は右、y は上 (tscircuit の向き)。
- **向き (どちらが 1 番か) は EasyEDA (JLCPCB のライブラリ) の同じ品番のフットプリントに合わせてある。** 配置表の回転が JLCPCB の側と同じ意味になるようにするため。J3 だけは例外 (下)。
- パッドの番号は rev D の KiCad のライブラリと同じ。例外は USB-C の殻の足 (KiCad では `1`〜`4`、ここでは `SH1`〜`SH4`。tscircuit は数字の名前のパッドを、名前つきのパッドの 1〜4 番目と同じピンとして扱ってしまうため)。回路のつながりは、この番号で rev D と比べている (`tools/netlist.ts`)。J1〜J3 のパッドは必ず名前 (`A5`、`B11`) で引く (`pin1` のような番号で引くと、並びの順になり取り違える)。
- パッドの大きさと位置は、メーカーの推奨ランドがあればそれに合わせる。`lib/footprints.test.ts` が検査しているのは、下の表で「合わせた」としたもの・J3・USB-C の並び・ピンの向きで、「差は小さい」「推奨なし」のものの数字は検査していない。作った基板のパッド (名前・位置・大きさ・層) がこの表のランドと同じであることは、製造用の出力を作るときに全部品で確かめている (`tools/origin.ts`)。
- 絵は [`__snapshots__/land-patterns.circuit-pcb.snap.svg`](../__snapshots__/land-patterns.circuit-pcb.snap.svg) (おもて) と [`land-patterns.circuit-bottom.snap.svg`](../__snapshots__/land-patterns.circuit-bottom.snap.svg) (うら。J3 の A 列)。

## 突き合わせの表

判定: **合わせた** = 推奨の数字にした / **合う** = EasyEDA 由来のままで推奨と同じ / **差は小さい** = 推奨と少し違うが、そのままにした (理由つき) / **推奨なし** = データシートに推奨ランドが無い / **未照合**。

#### J3 の耳

- J3 のデータシートは、部品の図 (1 枚目) と推奨の基板の図 (2 枚目) で数字が食い違う (耳の穴がキーの中心から 16.67 と 16.30、ピッチ 1.02 と 1.00 など)。部品の図の寸法は、推奨の基板の図よりそろって約 2.3% 大きいので、同じ寸法を別の縮尺で書いたものとみられる (推定)。ランドは推奨の基板の図どおり (穴は原点から ±14.3)。
- LCSC の属性は「With column」(柱つき)。**耳にあるのは通し穴ではなく、基板の ø2.0 の穴にはまる位置決めの突起とみられる (推定)。ねじで留められるかは分からない。**
- **発注の前に J3 を 1 個買って測る**: 耳は突起か穴か・径・左右の間隔 (28.6 か 28.97)・当たり面からの距離 (2.51 か 2.57)。

#### J1・J2 の差

- パッドは推奨 (長さ 1.14) より外へ 0.27 長く、内側は 0.11 短い (長さ 1.3、中心が 0.19 外)。
- 殻の足の長穴は 0.8 × 1.5 と 0.8 × 1.2 (推奨の読みは 0.6 × 1.7 と 0.6 × 1.4)。幅が 0.2 広く、長さが 0.2 短い。脚は入る (長さの向きの余裕は片側 0.2)。
- データシートの推奨では、口は基板の端から 0.49 出る。この基板は 0.99 出している (口の面をブラケットの外の面にそろえるため。[mechanical.md](mechanical.md))。**推奨より 0.5 多く張り出すので、殻の前の足から基板の端までが短い。配置の段階で確かめる。**

### 極性とピンの対応

データシートで確かめたもの: Q1 (1 = G、2 = S、3 = D)、Q2・Q3 (1 = G、2 = S、3 = D)、Q4 (1 = B、2 = E、3 = C)、LED (1 = アノード)。

**ダイオードの 1 番がどちらかは、データシートからは決まらない** (帯の側がカソード、とあるだけで番号が無い)。
EasyEDA の記号とフットプリントの対応に従っている: D1・D2 (SS54) は 1 番がアノード、D4 (SS34)・D5・D6・D7 は 1 番がカソード。
シルクの点はカソードの側に打つ。**発注の画面の配置の絵で、帯の向きを確かめる** ([manufacturing.md](manufacturing.md))。

## データの出どころと利用条件

- ランドの数字のもとは 2 つ: **EasyEDA / LCSC のライブラリ** (rev C・rev D の KiCad のライブラリが easyeda2kicad で取り込んだもの。向きと、推奨ランドの無い部品のパッド) と、**各メーカーのデータシート** (上の表)。`lib/footprints.ts` は、それらの数字を読んで書き直したデータで、EasyEDA のファイルそのものは入っていない。
- TP・はんだジャンパー・取り付け穴の寸法は KiCad の標準ライブラリと同じ値。
- 3D のモデルは外から取って入れていない。3D の絵の部品の形は `lib/cad.ts` が、データシートの外形の寸法と高さから簡単な形 (箱・足・殻) を組み立てる (このリポジトリのライセンスのまま)。EasyEDA / LCSC の 3D モデル (STEP / OBJ) は利用条件が分からないので使わない。
  - 形を描いた部品: 0603・0805・1206 のチップ、LED、FXL0630、SMA・SOD-123(F)、SOT-23(-6)・SOT-583・SOT-89・ESSOP-10・TSSOP-20、USB-C (J1・J2)、PCIe x1 のスロット (J3)、2×5 のヘッダ (J4)。
  - `lib/cad.ts` の表に無いフットプリントも自動で形が付く: 中央のパッドを 4 辺のパッドが囲めば QFN、パッドが 2×2 の 4 つなら水晶 (3225 など)、それ以外は外形 (`body`、無ければパッドの範囲) と `height` の箱。
  - モデルは `cad_component` に入るだけで、ガーバー・BOM・配置表には出ない。高さは検査の高さ (`height` / `HEIGHT_FALLBACK`) を超えないことを `lib/cad.test.ts` が見る。
- **EasyEDA / LCSC のライブラリの利用条件は未確認。** 公開のリポジトリに EasyEDA 由来のファイルをそのまま置くことはしていないが、数字 (パッドの寸法) は使っている。
- データシートの PDF はリポジトリに入れない。
